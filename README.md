# HydroPulse — Hydropower Bearing Vibration Forecasting

**FYP source code and datasets** for *Predictive Maintenance of Hydropower Plant Bearings Through Machine Learning-Based Vibration Forecasting*. HydroPulse is a **simulation-based research prototype**, not a production plant maintenance or SCADA system.

## Study scope

Forecast the next **10-minute** Turbine Guide Bearing (TGB) and Upper Guide Bearing (UGB) vibration values using 36 historical 10-minute observations (six hours) and four operational inputs per bearing. Six models were evaluated: Linear Regression, LSTM, and GRU, each trained separately for TGB and UGB.

November 2020 independent test RMSE:

| Bearing | Linear Regression | LSTM | GRU | Lowest RMSE |
|---|---:|---:|---:|---|
| TGB | 0.7122 | **0.6611** | 0.6648 | LSTM |
| UGB | **0.6077** | 1.1081 | 0.8378 | Linear Regression |

The original measured test results are in `results/final_model_comparison.csv`; synthetic simulation results are **separate**. RMSE, MAE, MAPE, and R² are also provided there.

## Data provenance and access

- **Primary data:** None collected directly; no live plant sensors were connected.
- **Secondary historical data:** Six CSV files for Neelum–Jhelum Hydropower Plant G1, June–November 2020 (reported total 23,997 valid timestamped observations). Train = June–August; validation = September; November = held-out independent test. October was examined but not selected as the primary validation period. The original data provider and permission to redistribute the CSVs have **not been verified**. **Keep this GitHub repository PRIVATE until the data owner or supervisor confirms sharing is allowed.** No reuse licence is asserted.
- **Synthetic data:** `data/synthetic/simulation_history.csv` consists of an export of the prototype's saved local simulation records, not independent plant observations. It is included to document the data generated by the prototype.
- **Derived data:** `data/prepared/`, `results/`, and `digital_twin/g1_integrated_replay.csv` were derived from the historical measurements and model outputs. These may be subject to the same redistribution restrictions as the source data.

## Requirements

Use **Python 3.11** as a recommended starting point. Dependencies are listed in `requirements.txt`. These are compatible-version ranges inferred from code imports rather than a verified lockfile; installation may require environment-specific adjustments.

From the project root in **Windows PowerShell**:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### Start synthetic forecasts

In one terminal:

```powershell
.\.venv\Scripts\python.exe digital_twin\live_scheduler.py --test
.\.venv\Scripts\python.exe digital_twin\live_scheduler.py
```

The first command tests one prediction cycle; the second starts the repeating scheduler. The scheduler creates `digital_twin/live_state.db` locally and writes prediction results approximately every 10 minutes after starting. Keep this terminal open.

### Run the dashboard

In a second terminal:

```powershell
.\.venv\Scripts\python.exe -m streamlit run dashboard\app.py
```

The dashboard uses a separate refresh cycle and reads saved SQLite results. It does not perform real-time inference itself.

### Reproduce the model analyses

Open the notebooks in numerical order from the `notebooks/` directory, where `Path('..')` is assumed to be the project root. Notebooks retain their original source cells but stored execution outputs were cleared to reduce repository size. The `07_digital_twin.ipynb` notebook is a **historical development notebook** and contains earlier `hydrotwin_core.py` and `hydrotwin_cad_viewer.py` filenames; the final application uses `digital_twin/hydropulse_core.py`, `digital_twin/hydropulse_cad_viewer.py`, and the simulator/scheduler scripts. Do not assume this historical notebook will execute end-to-end without updating its earlier paths.

## Important limitations

HydroPulse shows short-horizon vibration forecasts, not validated fault diagnosis, remaining useful life estimates, safety thresholds or a direct maintenance recommendation. The conceptual 3D rendering is not an as-built plant model. The project has not been validated against a real-time plant sensor feed.

**Security:** Do not upload credentials, `.env` files, `.streamlit/secrets.toml`, local databases, or virtual environments. Saved Python pickle models should be loaded only from a trusted source.
